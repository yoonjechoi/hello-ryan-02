# 갤러리 업로드 (gallery-upload v2 — 자유 업로드)

내가 만든 작품을 **헬로 라이언 갤러리**에 올린다. 사이트에서 로그인해 받은 **업로드 키**로
내 계정에 연결되고, 모두가 갤러리에서 회차별로 함께 본다.

> 엔진: 이 스킬 폴더의 `scripts/upload.mjs` (윈도우·맥 동일, 외부 의존성 0, Node 내장만 사용).

## v1과 달라진 점 (자유 업로드 + 프라이버시 계층)

- **무엇이든 올린다** — `web.html` 강제 없음. HTML·CSS·JS·이미지(png/jpg/webp/gif/svg)·마크다운·텍스트, 원하는 조합으로.
- **여러 작품** — 작품 이름(`--name`)이 다르면 **새 작품**으로 나란히 올라간다.
- **다시 올리기** — 같은 이름으로 다시 올리면 **그 작품이 통째로 업데이트**된다(이전 파일은 정리됨).
- **대표 파일 자동** — `index.html` > `web.html` > 첫 HTML > 첫 파일 순으로 갤러리 미리보기 대표가 정해진다. `--rep 파일명` 으로 지정도 가능.
- **전체 생성물 zip 아카이브 (자동, 비공개)** — 폴더를 올리면 그 폴더 전체(인터뷰 원문·중간 산출물 포함)가 `archive.zip`으로 **비공개 버킷**에 함께 보관된다. 갤러리에서 남들이 보는 건 ①배포 주소 ②주인이 공개하기로 고른 파일뿐. **아카이브는 주인과 운영진만** `--get-archive`(또는 `/api/archive`)로 열람. 끄려면 `--no-archive`.

## 로그인 = 사이트에서 한 번. CLI는 키만 나른다.

- 로그인은 브라우저에서 1회. 사이트 마이페이지 → "내 업로드 키"의 한 줄(`내 브랜드 갤러리에 올려줘 키: ...`)을 그대로 붙여넣으면 된다.
- 스킬이 그 줄에서 **키만 빼서 로컬에 저장**(`~/.hello-ryan/upload-key`) → 다음부턴 "올려줘"만 해도 된다.

## 진행 순서 (리더가 직접)

1. **키 확보:** 메시지에 `키:`(또는 `key:`)가 있으면 그 값을 쓴다(`--key`로 전달하면 자동 저장). 없으면 저장된 키. 그것도 없으면 *"사이트에서 로그인하고 받은 한 줄을 붙여넣어 주세요"* 안내하고 멈춘다.
2. **올릴 것 정하기:** 사용자가 가리킨 폴더/파일을 쓴다. 애매하면 *"어떤 폴더(또는 파일들)를 올릴까요?"* 라고 묻는다. 폴더면 그 안의 웹파일·이미지·문서를 자동 수집한다.
3. **공개 범위 확인(중요):** *"갤러리에서 남들에게 보여줄 파일은 이것들이에요. 빼고 싶은 게 있나요?"* — 인터뷰 원문 등 민감한 파일이 공개 목록에 들어있으면 반드시 짚어준다. 뺀 파일도 **비공개 아카이브(zip)에는 담겨서 본인/운영진은 볼 수 있음**을 알려준다.
4. **작품 이름:** 대화에서 정해진 이름이 있으면 그걸, 없으면 폴더 이름을 제안하고 확인받는다. **같은 이름 = 업데이트, 다른 이름 = 새 작품**임을 알려준다.
5. **배포 주소(꼭 묻기):** *"인터넷에 배포한 내 주소가 있으면 알려주세요 — 갤러리 카드에 같이 걸려요."* → `--deploy <URL>`. 없으면 생략.
6. **미리보기(게이트):** 먼저 `--dry-run`으로 **무엇이 공개되고 무엇이 아카이브로 가는지 보여주고** "이대로 올릴까요?" 확인받는다.
7. **전송:** 확인되면 `--dry-run` 빼고 실행. 끝나면 **갤러리 주소(viewUrl)** 를 보여준다.
8. **교육:** *"다른 작품도 이름만 바꿔서 또 올릴 수 있어요. 같은 이름은 업데이트. 전체 과정 기록(zip)은 비공개라 본인과 운영진만 봐요."*

## 실행 명령

```bash
# 5) 미리보기 — 전송 안 하고 무엇이 올라가는지 확인
node <이-스킬-폴더>/scripts/upload.mjs <폴더나 파일들> --name "작품 이름" --key "<키>" --dry-run

# 6) 실제 전송 (키는 한 번 저장되면 생략 가능)
node <이-스킬-폴더>/scripts/upload.mjs <폴더나 파일들> --name "작품 이름"

# 예시
node scripts/upload.mjs my-site/ --name "나의 첫 사이트"                 # 폴더째
node scripts/upload.mjs index.html style.css logo.png --name "명함 사이트" # 파일 골라서
node scripts/upload.mjs my-site/ --name "나의 첫 사이트" --deploy "https://..." # 배포주소 포함
```

옵션: `--tagline "한 줄"` `--desc "설명"` `--category "분류"` `--rep index.html`
`--private <파일|폴더>`(비공개 첨부) `--episode <회차슬러그>` `--endpoint <URL>`
`--archive <폴더>`(전체 zip 대상 지정, 기본=업로드한 폴더) `--no-archive`(zip 생략)

```bash
# 내 아카이브(전체 생성물 zip) 받기 — 주인 또는 운영진만
node <이-스킬-폴더>/scripts/upload.mjs --get-archive <slug>
```

## 서버 payload 계약 ⭐ (서버 `/api/submit` 과 일치)

```jsonc
POST <endpoint>  (application/json)
{
  "uploadKey": "<키>",
  "brand": { "name": "작품 이름(필수)", "tagline": "…", "description": "…",
             "category": "…", "colors": {...}, "fonts": {...}, "ownDeployUrl": "… | null" },
  "files":        { "index.html": "<html…>", "style.css": "…" },   // 공개 텍스트 파일
  "filesBase64":  { "logo.png": "<base64>" },                       // 공개 바이너리(이미지 등)
  "private":      { "메모.md": "…" },                               // 비공개 텍스트
  "privateBase64":{ "archive.zip": "<base64>" },                    // 비공개 바이너리 — 전체 생성물 zip이 여기로
  "representative": "index.html",                                   // 선택
  "episodeSlug": "ep03"                                             // 선택(없으면 이번 회차 자동)
}
// 응답: { "ok": true, "slug": "uFx5gv59", "viewUrl": "/g/uFx5gv59/index.html", "galleryUrl": "/g" }
```

제한: 파일당 20MB(공개·비공개/아카이브 zip 동일), 요청 전체 40MB, 공개 파일 최소 1개.
파일명은 영숫자·`.`·`-`·`_` 만(한글 파일명은 엔진이 자동으로 안전한 이름으로 바꾸고 알려준다).

**아카이브 열람 계약** — `POST /api/archive` `{ "uploadKey": "<키>", "slug": "<작품slug>" }`
→ 본인 작품이거나 운영진(role=instructor|admin)이면 `{ ok, files: [{name, url(signed, 10분)}] }`.
틀린 키 401 · 남의 작품 403 · 없는 작품/빈 아카이브 404. 공개 서빙(`/g/<slug>/<file>`)으로는 절대 안 나온다.

## 게이트 + 교육

- 전송 전 **반드시 dry-run으로 보여주고** 확인받는다(뭐가 올라가는지 보고 올림).
- 비공개(`--private`)는 갤러리에 안 뜨고 진행자만 본다고 안내.
- 교육: *"키는 한 번만 넣으면 저장돼요. 다음엔 '갤러리에 올려줘'만 하면 돼요."*

## 에러 핸들링 (엔진이 자동 처리)

- 키 없음 → 사이트 로그인 안내 후 멈춤(임의 진행 금지).
- **키 오류(HTTP 401/403)** → "키를 다시 확인해 주세요"로 멈춤. 이메일 폴백 안 함.
- **서버 불가(404·5xx)/네트워크 실패** → `_upload-payload.json` 저장 + 진행자 이메일 폴백 안내(`HELLO_RYAN_FALLBACK_EMAIL`).
- 검증 오류(HTTP 400/413) → 서버 응답을 보여주고 멈춤. 추측 재시도 금지.
